# BS Intern 邮件模版转换规则

将 pandoc 输出的原始 markdown 转换为结构化邮件模版。
转换分三个阶段：清理 → 语义识别 → 结构化输出。

---

## 阶段一：清理 Pandoc 格式残留

pandoc 从 docx 转 markdown 时会产生样式标记、转义字符等残留，必须先清理。

| 残留 | 示例 | 处理 |
|------|------|------|
| 样式标记 | `[文本]{.mark}`, `[文本]{.underline}` | 删除标记，保留文本 |
| 双层链接 | `[[email]{.underline}](mailto:email)` | 简化为 `email` |
| 转义符号 | `\@`, `\<`, `\>`, `\[`, `\]` | 还原为原始字符 |
| 转义横线 | `\-\-\-\-\-` | 删除或还原为 `---` |
| 嵌入图片 | `![](media/image1.png){width=...}` | 替换为 `[附截图]` |
| HTML 表格 | `<table>...</table>` | 转为 markdown 表格 |
| 尺寸属性 | `{width="6.5in" height="3.18in"}` | 删除 |

## 阶段二：语义识别

### 1. 收件人与抄送：固定 vs 占位符

判断优先级从高到低：

1. **在 fixed_roles 列表中** → 仅保留邮箱地址，去掉姓名
   - `Mo NS <mo.ns@nsdigital.io>` → `mo.ns@nsdigital.io`
   - `BigOrange NS <orange@nsdigital.io>` → `orange@nsdigital.io`（业务线专属角色）

2. **不在列表中，但有具体邮箱** → 仅保留邮箱地址，去掉姓名
   - `cheng nannan <cnnyjy@gmail.com>` → `cnnyjy@gmail.com`

3. **无邮箱，仅有角色描述** → 转为占位符
   - `业务邮箱群组` → `{business_group_email}`
   - `业务leader` / `XX业务leader` / `Product leader` → `{business_leader}`
   - `客户关键人邮箱` → `{client_contact_email}`

### 2. 正文中的可变内容 → 占位符

原始模版中用以下方式标记可变内容，统一转为 `{placeholder}`：

| 原始标记方式 | 示例 | 转为 |
|-------------|------|------|
| `XX` / `xx` / `XXX` | `XX业务线`, `xx项目号` | `{business_line}`, `{project_id}` |
| 方括号描述 | `[业务线名称]`, `[客户公司全称]` | `{business_line}`, `{client_company}` |
| 冒号后空白 | `主体：`, `平台:` | `主体：{account_entity}`, `平台：{platform_name}` |
| 角色描述文字 | `客户关键人邮箱` | `{client_contact_email}` |

占位符命名：小写字母 + 下划线，优先复用 `conversion-config.yaml` 的 `placeholders` 库。
同一语义跨模版使用同一名称。

### 3. 邮件主题

从 `conversion-config.yaml` 的 `subject_labels` 匹配标签。
格式：`【标签】{关键信息} {日期}`
同时生成主题示例行（若原文有「参考标题」或「参考邮件」，直接引用）。

### 4. 审批流程

识别 `@姓名 + 请审批/请确认` 模式，保留 `@` 提及格式。
固定审批人（在 fixed_roles 中）保留原名，可变审批人转为占位符。

### 5. 表格

| 类型 | 特征 | 处理 |
|------|------|------|
| 待填写（数据行为空） | 表头有字段名，数据行大量空白 | 转为字段列表：`- 字段名：{placeholder}` |
| 已有数据 | 表头和数据行均有值 | 保留 markdown 表格 |
| 固定值单元格 | 特定单元格有预填值 | 保留原值，不转占位符 |

### 6. AI 操作提示

原文中的高亮操作指令（pandoc 转为 `{.mark}` 的提示性文字）：
- `[需要AI行动：...]`
- `[需要附截图：...]`

保留到输出模版的「使用指南 → 注意事项」中。

### 7. 多模版文件

部分 docx 包含多个邮件子模版（如「增加 IP」+「更新 IP」）。
保持在同一个 markdown 文件中，用二级标题区分每个子模版，
每个子模版独立拥有完整的四段结构（标题降为 ###）。

```
# 更新/增加IP邮件申请

## 子模版 1：增加 IP
### 📋 基本信息
### 📥 收件人信息
### 📤 邮件正文
### 💡 使用指南

---

## 子模版 2：更新 IP
### 📋 基本信息
...
```

## 阶段三：结构化输出

每个模版（或子模版）输出为四段式结构：

### 📋 基本信息

| 字段 | 取值 |
|------|------|
| 模版 ID | 文件名（去后缀，中文转拼音或保留原名） |
| 版本 | v1 |
| 更新日期 | 转换当日 |
| 状态 | active |
| 适用场景 | 从邮件内容推断 |

### 📥 收件人信息

- **收件人**：固定邮箱保留，角色描述转占位符
- **抄送**：列表格式，每行一个
- **邮件主题**：含占位符的主题模板
- **主题示例**：用具体值替换的完整示例

### 📤 邮件正文

- 问候语（Dear Team，/ Hi {name}，）
- 正文（占位符替换后的内容）
- 审批流程（如有）
- 签名（如有）

### 💡 使用指南

- **变量替换说明表**：

  | 占位符 | 说明 | 是否必填 | 示例 |
  |--------|------|---------|------|
  | `{business_line}` | 业务线名称 | 必填 | Defi |

- **固定信息说明**：列出模版中不需替换的固定收件人/抄送
- **AI 操作提示**：原文中的高亮操作指令（如有）
- **注意事项**：附件要求、审批前自检等
