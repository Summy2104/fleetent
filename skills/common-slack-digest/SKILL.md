# Slack 消息总结

从 Slack 频道获取历史消息，根据用户意图生成不同类型的总结。

## 使用模式

| 模式 | 触发示例 | 输出 |
|------|----------|------|
| **讨论总结** | `总结 #dev-ai 今天的讨论` | 会议纪要格式 |
| **活动摘要** | `#product 这周发生了什么` | 频道动态概览 |
| **知识提取** | `#dev-ai 有什么重要决策？` | 决策/结论列表 |
| **搜索总结** | `搜索 #dev-ai 关于 API 的讨论` | 搜索结果 + 总结 |

## 工作流程

```
解析输入 → 识别模式 → 获取消息 → 预处理 → 生成总结 → 输出
```

### Step 1: 解析输入参数

从用户输入中提取：

| 参数 | 解析方式 | 默认值 |
|------|----------|--------|
| 频道 | `#频道名` 或 `C0XXXXXX` | 当前频道 |
| 时间范围 | `今天`/`这周`/`过去N天` | 24 小时 |
| 搜索词 | `关于xxx`/`搜索xxx` | 无 |

### Step 2: 识别使用模式

根据关键词自动判断：

```
- "讨论/会议/聊了什么" → 讨论总结
- "发生了什么/活动/动态" → 活动摘要
- "决策/结论/方案/知识" → 知识提取
- "搜索/关于xxx" → 搜索总结
- 无明确意图 → 默认「活动摘要」
```

### Step 3: 获取 Slack 消息

通过 Slack MCP 工具 `slack__conversations_history` 获取频道消息：

```
slack__conversations_history(channel_id="C0XXXXXX", limit="1d")
```

> Slack MCP server 需在 agent.yaml 中挂载。若未挂载或对应 token 未配置，说明该 agent 未配置 Slack 数据访问，应跳过 Slack 数据采集。
> 搜索总结模式可用 `slack__conversations_search_messages`；展开 thread 用 `slack__conversations_replies`。

### Step 4: 消息预处理

1. **过滤**：移除 Bot 消息、纯表情、系统通知
2. **合并**：连续同一人的消息合并
3. **线程展开**：将 thread 回复关联到主消息
4. **时间标注**：保留时间戳

### Step 5: 询问输出格式（可选）

如用户未明确指定，询问：

```
消息已获取（共 N 条），你想要哪种输出格式？
1. 详细报告 - 完整的结构化分析
2. 简洁摘要 - 3-5 个要点
3. 时间线 - 按时间顺序的关键事件
```

### Step 6: 生成总结

根据模式和输出格式，使用对应模板生成结果（见 `references/templates.md`）。

## 异常处理

| 情况 | 处理方式 |
|------|----------|
| 无频道权限 | 提示：Bot 未加入该频道，请先邀请 Bot |
| 频道不存在 | 提示：找不到频道，请确认名称或使用频道 ID |
| 消息数为 0 | 提示：该时间范围内没有消息，建议扩大范围 |
| 消息过多（>500） | 建议缩小时间范围，或分批处理 |
| API 限流 | 提示稍后重试 |
| 搜索无结果 | 提示：未找到相关讨论，建议换个关键词 |
| 私密频道 | 提示：请确认 Bot 已被添加到该频道 |

### 降级策略

```
API 获取失败 → 重试一次 → 仍失败 → 提示用户手动粘贴消息
```

## 首轮契约（用于测试与实现对齐）

1. direct（信息充分）
- 当输入已提供关键上下文时，首轮应直接给出结构化结果或明确执行步骤。
- 输出应包含核心结论与下一步动作，不依赖额外反问才能开始。

2. clarify（信息不足）
- 当输入缺少关键字段时，首轮应先说明缺口并要求补充信息。
- 最小补充项建议包含：目标/范围、必要上下文、时间或对象信息。
- 此场景首轮不应直接宣称“已完成最终处理”。
