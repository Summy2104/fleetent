## ADDED Requirements

### Requirement: 断连异常归类为 mcp_disconnect 并据标志位重连

当 MCP 服务的工具调用因连接级断连失败（HTTP 服务不可达、stdio 子进程死亡/会话失活）时，平台 SHALL 将该断连判定为 `mcp_disconnect` 分类，并依据该分类在错误分类表中的 `should_retry` 标志位决定是否尝试重连。平台 MUST NOT 在连接维护逻辑中重复硬编码「断连该不该重连」的判断，而是消费错误分类层定义的标志位（读分类表，不修改其标志位定义）。

#### Scenario: 断连归类为 mcp_disconnect
- **WHEN** 某 MCP 服务的工具调用因连接级断连失败
- **THEN** 该断连被归类为 `mcp_disconnect`，其 `should_retry` 标志位为真，平台据此进入重连流程

#### Scenario: 会话过期不归类为连接断连
- **WHEN** 某 `http` 服务的工具调用收到 HTTP 404（会话过期）
- **THEN** 该响应不被归类为 `mcp_disconnect`，不触发连接级降级与重连（由会话连续性机制单独处理）

### Requirement: 连接健康状态按服务隔离

平台 SHALL 为每个已注册 MCP 服务维护连接健康状态（健康 / 降级 / 永久不可用），并按服务实例隔离持有。健康状态 MUST NOT 置于模块级可变全局状态。某服务的健康状态变化 MUST NOT 影响其他服务。

#### Scenario: 单服务降级不影响其他服务
- **WHEN** 一个 MCP 服务进入降级状态而另一服务保持健康
- **THEN** 降级服务的工具调用返回不可用信号，健康服务的工具调用正常

### Requirement: 周期性探活检测断连

平台 SHALL 周期性对已注册服务探活：`http` 服务发送轻量请求判活，`stdio` 服务检查子进程是否存活。探活检测到断连时，平台 MUST 将该服务转入降级状态并触发重连。探活间隔 SHALL 可配置/可注入，默认值内置以保证零配置可用。

#### Scenario: 探活发现 HTTP 服务不可达
- **WHEN** 某 `http` 服务在探活时不可达
- **THEN** 平台将该服务转入降级状态并触发重连

#### Scenario: 探活发现 stdio 子进程不存活
- **WHEN** 某 `stdio` 服务的子进程在探活时已不存活
- **THEN** 平台将该服务转入降级状态并触发重连

### Requirement: 指数退避重连与永久不可用标记

服务断连后，平台 SHALL 按指数退避重连，退避间隔从 1 秒起翻倍增长，封顶为 60 秒。连续重连失败达到阈值后，平台 MUST 将服务标记为永久不可用并停止自动重连，仅可经手动触发重连恢复。退避基数、上限与失败阈值 SHALL 可配置/可注入。

#### Scenario: 重连按指数退避增长且封顶
- **WHEN** 服务断连后连续重连失败
- **THEN** 重连间隔按 1s→2s→4s→… 翻倍增长，最长不超过 60s

#### Scenario: 连续失败达阈值标记永久不可用
- **WHEN** 服务连续重连失败次数达到配置阈值
- **THEN** 平台将该服务标记为永久不可用并停止自动重连

#### Scenario: 手动触发重连恢复永久不可用服务
- **WHEN** 对一个永久不可用的服务手动触发重连且服务此时可达
- **THEN** 平台重新连接成功并将服务恢复为健康状态

### Requirement: 重连成功后自动恢复

服务重连成功后，平台 SHALL 将其健康状态恢复为健康、重置退避计数，其工具 MUST 自动重新可调用，无需手动干预。

#### Scenario: 断连服务重连成功后工具恢复
- **WHEN** 一个降级中的服务后台重连成功
- **THEN** 平台将其恢复为健康状态、重置退避计数，其工具调用恢复正常返回结果

### Requirement: 降级期间工具调用返回不可用信号

当服务处于降级或永久不可用状态时，对其工具的调用 MUST 返回明确的「服务暂时不可用」结果，而非裸抛异常或静默卡住。该调用 MUST NOT 进入实际的网络请求或子进程调用，且 MUST NOT 阻断其他服务工具或当前对话。

#### Scenario: 降级服务工具返回暂时不可用
- **WHEN** agent 调用一个处于降级状态服务的工具
- **THEN** 该调用返回「服务暂时不可用」结果，不抛异常、不卡住，其他服务工具不受影响
